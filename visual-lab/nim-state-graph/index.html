Combinatorial games · directed state spaces

Nim as a graph

Take counters from one pile—or make the same move by following an arrow. Every node is a position and whose turn it is; every directed edge is one legal move. An optimal computer reveals that the game is really a navigation problem through a finite graph.

Starting position

Build a Nim game

Choose any small collection of piles. The graph folds together positions that differ only by pile order, keeping the complete state space readable.

Preset
Piles

1–6 piles, with 1–12 counters each. Larger complete graphs are declined before they can slow the page.

First move

Ready to build the complete graph.

How the computer chooses

XOR all pile sizes to get the nim-sum. A zero nim-sum is losing for whoever moves next. Whenever possible, the computer follows an edge back to zero. From zero, no forced win exists, so every legal move is equally optimal.

Arrow keys rotate the view, plus and minus zoom, and R resets it. The bright trail records the played path. Nodes outside the directed future cone are dimmed, with past states dimmed most strongly. Only highlighted neighboring nodes can be chosen as moves.

The two terminal nodes include whose turn comes next: an empty board with the computer to move means Victory, because you took the last counter; an empty board with you to move means Defeat. Pile-order symmetries are folded together in the graph, so positions such as [5, 3, 1] and [1, 5, 3] share a node without changing the game.
